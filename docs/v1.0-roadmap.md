# v1.0 Readiness

This proposed checklist preserves the release-readiness goals from PR #49.
It is not a release commitment or evidence that the gates have passed. The
current release line is v0.4.x; see [Roadmap](roadmap.md) for shipped and deferred
features. Zig 0.16 and 0.17 compatibility remains in scope.

## Stabilize and verify

- [ ] Run offline unit, module, and comprehensive tests on both supported Zig
      versions, recording the exact toolchain and commit.
- [ ] Exercise live-engine client and module-authoring paths with the pinned
      Dagger engine; record platform-specific limitations.
- [ ] Audit documented public APIs against generated bindings and identify any
      reachable unimplemented paths.
- [ ] Verify dependency installation, copyable examples, and migration guidance
      from a clean consumer project.

## Release evidence

- [ ] Keep package metadata, SDK version constants, release manifest, and current
      documentation aligned without rewriting historical release records.
- [ ] Verify each release's SBOMs, signatures, and provenance using the
      [Release Checklist](RELEASE_CHECKLIST.md) and [Compliance](compliance.md).
      The existence of a workflow or badge alone does not establish assurance.
- [ ] Build documentation, check links, and review keyboard navigation and
      contrast in each supported theme.

## Platform and community decisions

- [ ] Decide the supported platform matrix from runtime evidence. Windows
      remains planned until its engine/session paths are validated.
- [ ] Decide which C ABI, native SPIFFE, and code-generation features belong in
      the v1.0 public contract; keep incomplete features explicitly experimental.
- [ ] Review the current Dagger Community SDK process and maintainer capacity
      before making an application or compatibility commitment.

No target release dates, milestone IDs, SDK acceptance, or platform-parity
claims are implied. Track concrete implementation work in reviewed issues.
