# dagger-zig v0.3.4 — Community Update

## The headline

**`dagger call` now works.** This release fixes the core runtime path that prevented Zig modules from loading in the Dagger engine. If you tried to use `dagger-zig` before and hit `failed to call module to get functions: call constructor: exit code: 1`, this is the fix.

## What was broken

The Zig SDK library lived at the repository root (`src/`), one level above the `sdk/` directory that the Dagger engine clones when a user references the SDK. When `ModuleRuntime` tried to build a user's Zig module inside the engine container, `@import("dagger_sdk")` had nothing to resolve against — the library wasn't there. Codegen compounded the problem by emitting a `dagger.gen.zig` that imported `dagger_sdk` without declaring the dependency or generating any build files.

The result: every `dagger call` and `dagger develop` against a Zig module failed at the constructor stage.

## What we fixed

1. **Vendored the library inside the SDK module.** Moved `src/` → `sdk/lib/src/` so the Zig library ships inside the SDK module that the engine clones. Added a consumer-facing `sdk/lib/build.zig` + `build.zig.zon` that exposes `dagger_sdk` via `b.dependency()`.

2. **Rewrote `ModuleRuntime`.** Now mounts `sdk/lib` (the Zig library, not the Go bootstrap tree) at `/sdk-lib`. The build script symlinks `/sdk-lib` → `.dagger-sdk-lib` so the generated `build.zig.zon`'s relative `.path` resolves regardless of the module's source subpath.

3. **Rewrote `Codegen`.** Now emits three files for every user module:
   - `build.zig` — wires `dagger_sdk` as a dependency and installs a `module` executable via the `module-runtime` step
   - `build.zig.zon` — declares the `dagger_sdk` path dependency (with the `fingerprint` field Zig 0.16 requires)
   - `internal/dagger/dagger.gen.zig` — re-export shim so `@import("dagger")` works too

4. **Fixed the CI pipeline module.** The `ci/pipeline/build.zig` referenced `../../sdk/lib/src/root.zig` directly, which doesn't exist inside the container. Switched to `b.dependency("dagger_sdk", ...)` with a proper `build.zig.zon`.

5. **Forked otel-go** to drop vulnerable transitive dependencies from the Go SDK bootstrap.

6. **Applied `zig fmt`** to all unformatted source files.

## Verified end-to-end

```
$ dagger develop
# → generated build.zig + build.zig.zon + internal/dagger/dagger.gen.zig

$ dagger call hello
hello from dagger-zig module runtime
```

The full runtime path — codegen, ModuleRuntime, Zig build in-container, entrypoint dispatch, function call — works.
